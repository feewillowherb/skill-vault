# 技术集成方案

## 安装与分发

### 方式一：全局 Claude Code Skill（推荐）

类似 `guess-governance` 的安装方式，安装到用户的全局 skills 目录：

```
~/.claude/skills/reasoning-annotate/
└── skill.md
```

安装命令（手动）：
```bash
mkdir -p ~/.claude/skills/reasoning-annotate
# 将 skill.md 内容写入
```

**优点**：
- 一次安装，所有项目生效
- 不需要修改 OpenSpec 源码
- 与 guess-governance 模式一致，用户熟悉

### 方式二：项目级 Skill

安装在项目的 `.claude/skills/` 或 `.agents/skills/` 目录：

```
my-project/
├── .claude/skills/reasoning-annotate/
│   └── skill.md
├── .openspec/
│   └── reasoning-categories.csv
└── ...
```

**优点**：
- 随项目版本控制，团队共享
- 可以与项目级分类表绑定

### 方式三：OpenSpec 内置 Skill（未来）

在 OpenSpec 的 skill 模板系统中注册（需修改 OpenSpec 源码）：

```typescript
// repos/openspec/src/core/shared/skill-generation.ts
export function getSkillTemplates(workflowFilter?: readonly string[]): SkillTemplateEntry[] {
  const all: SkillTemplateEntry[] = [
    // ... 现有 skills
    { template: getReasoningAnnotateSkillTemplate(), dirName: 'openspec-reasoning-annotate', workflowId: 'reasoning-annotate' },
  ];
  // ...
}
```

**现状**：此方案需要 OpenSpec 上游接受合并，目前不做。优先使用方式一或方式二。

## 触发机制

### Auto-Trigger 通过 Description 匹配

skill.md 的 YAML frontmatter `description` 字段被 AI harness 用于 auto-trigger 匹配。当前设计：

```yaml
description: Annotate high-value AI reasoning in OpenSpec proposals using a user-AI co-maintained classification table. Use when generating or reviewing OpenSpec proposals, designs, or specs to highlight reasoning that matches subscribed categories. Non-blocking — annotations only, never halts workflow.
```

**匹配关键词**：
- `annotate` / `标注`
- `reasoning` / `推理`
- `OpenSpec proposals` / `OpenSpec 提案`
- `classification table` / `分类表`

**预期触发场景**：
1. 用户运行 `/opsx:propose` 生成提案后
2. 用户说"标注这个提案的推理内容"
3. 用户说"检查 proposal.md 的推理亮点"
4. 用户说"review the reasoning in the design"

### 显式触发

用户也可以直接调用：
- `/reasoning-annotate` — 对当前 change 的 proposal.md 执行标注
- `/reasoning-annotate suggest` — 基于未匹配推理建议新分类

## 与 guess-governance 的协作

### 共存场景

当两个 skill 同时安装时，它们在同一提案产物上各自执行：

```
OpenSpec propose 流程
    │
    ├── guess-governance
    │   ├── 提取 Facts / Assumptions / Decisions Needed
    │   ├── 计算 Guess Ratio / Risk
    │   ├── 可能阻断（>35% ratio）
    │   └── 嵌入 governance section 到 proposal.md
    │
    └── reasoning-annotate
        ├── 加载 CSV 分类表
        ├── 扫描推理段落
        ├── 匹配订阅分类
        └── 输出标注摘要（可选追加到 proposal.md）
```

### 信息流

- guess-governance 的 Assumptions 表中的条目可作为 reasoning-annotate 的输入
- reasoning-annotate 识别的推理段落中，guess-governance 的 L3 items 应自动标记为安全相关（如果 security 分类已订阅）
- 两者互不修改对方的产物

## OpenSpec config.yaml 集成（可选增强）

如果用户希望将 reasoning-annotate 的分类表路径配置到 OpenSpec 的 `config.yaml` 中：

```yaml
schema: spec-driven

context: |
  Tech stack: TypeScript, Node.js

rules:
  reasoning-annotate:
    - Always annotate architecture decisions
    - Security reasoning is high priority for this project

reasoning-categories: .openspec/reasoning-categories.csv
```

**注意**：这需要 OpenSpec 支持 `reasoning-categories` 配置项，目前属于未来增强，不影响 skill 独立运行。

## CSV 读取实现参考

Skill 指令中描述的 CSV 读取流程（供 AI agent 执行）：

```bash
# 1. 检查项目级
if [ -f ".openspec/reasoning-categories.csv" ]; then
  cat .openspec/reasoning-categories.csv
# 2. 检查全局级
elif [ -f "$HOME/.openspec/reasoning-categories.csv" ]; then
  cat "$HOME/.openspec/reasoning-categories.csv"
# 3. 使用内置默认
else
  echo "Using built-in defaults"
fi
```

AI agent 读取 CSV 后，在内存中解析为分类列表，过滤 `subscribed=true` 的行，用于后续匹配。

## 局限性与风险

| 局限 | 影响 | 缓解措施 |
|------|------|---------|
| CSV 解析依赖 AI 理解，非程序化 | 复杂 CSV（含逗号、换行）可能解析错误 | 保持 CSV 简单，description 不含逗号 |
| Auto-trigger 可能不准确 | 可能不触发或误触发 | description 中包含足够多的触发关键词 |
| 分类匹配主观性强 | 不同 AI session 可能匹配结果不一致 | 提供足够清晰的 description 字段 |
| 不支持跨 artifact 追踪 | 只标注单个文件内的推理 | 未来可扩展为 change 级别汇总 |
| 与 guess-governance 的 Assumptions 重叠 | 同一段内容可能被两个 skill 重复标注 | 明确分工：governance 管"假设"，annotate 管"推理" |

## 后续增强方向

1. **分类表管理命令**：`/reasoning-annotate manage` 交互式编辑 CSV
2. **跨 change 统计**：汇总多个 proposal 的标注趋势
3. **OpenSpec 内置集成**：提交到 OpenSpec 上游作为可选 skill
4. **分类表市场**：预设不同领域的分类模板（金融、电商、SaaS 等）
5. **标注持久化存储**：JSON 格式的标注历史，支持趋势分析
