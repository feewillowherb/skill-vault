# BMAD-METHOD → Topic → OpenSpec 工作流设计

## 1. BMAD-METHOD 设计哲学

| 维度 | BMAD-METHOD |
|------|-------------|
| 设计哲学 | 全周期规划（Full Lifecycle Planning） |
| 核心隐喻 | 建筑事务所：概念设计 → 详细图纸 → 施工计划 → 分步建造 |
| 知识管理 | 显式、持久化 |
| 人类角色 | 协作者（Collaborator） |
| AI 角色 | 引导者（Facilitator） |

### "引导人类思考"模式

**BMAD-METHOD**: AI 引导 → 人类思考 → AI 记录 → 人类决策
- AI 是引导者和记录者
- 人类是主要思考者
- 深度、创造性强、依赖人类判断力

## 3. 工作流设计：BMAD → Topic → OpenSpec

### 3.1 工作流概述

```
Epic 级需求
    ↓
BMAD-METHOD 分析规划
    ↓
生成制品 → topic 文件夹/
              ├── proposal.md    (OpenSpec /opsx:propose 输入)
              └── design.md      (概要设计，OpenSpec /opsx:apply 参考)
    ↓
导入 OpenSpec 执行 propose → apply 流程
```

### 3.2 Topic 文件夹规范

**命名**: 使用 topic 名称，kebab-case 格式（如 `plan-methodology-research`）

**文件结构**:
```
topic-name/
├── proposal.md   ← 需求提案，描述 Why / What Changes / Capabilities / Impact
└── design.md     ← 概要设计，描述 Context / Goals / Decisions（不需要非常细节）
```

**设计原则**:
- `proposal.md` 是主体，描述 epic 级需求的动机和变更范围
- `design.md` 保持概要级别，关注关键设计决策和方向，不深入实现细节
- 两个文件共同构成一个 topic，可直接被 OpenSpec 消费

### 3.3 OpenSpec 对接

Topic 文件夹是 OpenSpec 的导入单元：

| 阶段 | 文件 | OpenSpec 操作 |
|------|------|--------------|
| 提案 | `proposal.md` | `/opsx:propose` 输入 |
| 设计 | `design.md` | `/opsx:apply` 参考 |

导入 topic 后，OpenSpec 自动识别 `proposal.md` 和 `design.md`，按序执行 propose → apply 工作流。

## 4. 总结

| 要点 | 描述 |
|------|------|
| BMAD 生成制品 | 使用 BMAD-METHOD 对 epic 级需求进行规划，输出 proposal + design |
| Topic 即单元 | 文件夹名 = topic 名，包含两个标准制品文件 |
| design 保持概要 | design.md 不需要非常细节，聚焦关键决策和方向 |
| OpenSpec 直接消费 | 导入 topic 文件夹即可启动 OpenSpec 工作流 |
