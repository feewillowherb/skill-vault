# Plan 方法论调研总览

## 调研概述

本次调研围绕 **"AI 辅助开发中的 Plan-then-Execute 方法论"** 这一主题，对 BMAD-METHOD 进行了深入分析，并提出了基于 BMAD 的自适应分级规划方案。

**调研日期**: 2026-05-18
**调研对象**: BMAD-METHOD v6
**调研来源**:
- BMAD-METHOD 源码: `repos/bmad-method`

## 研究背景

AI 编程工具正在从"即时生成代码"的模式转向"先规划后执行"的结构化方法论。这一转变的核心动机是：

1. **降低返工成本**: 未规划直接编码导致大量架构返工
2. **提升代码质量**: 结构化规划产生更可维护的代码
3. **增强人类控制**: 人在回路中审批和修正计划
4. **上下文管理**: 分阶段传递上下文，避免 LLM 上下文窗口溢出

## 核心发现

### BMAD-METHOD

| 维度 | 特征 |
|------|------|
| 定位 | 全生命周期 AI 敏捷开发框架 |
| 核心模式 | Analysis → Planning → Solutioning → Implementation 四阶段 |
| 人类控制 | 协作式（每个 Agent 引导用户思考） |
| 上下文管理 | 显式（文件化渐进传递） |
| 适用规模 | 想法级到企业级 |
| 制品管理 | 独立文档文件体系 |

### 关键洞察

```
BMAD-METHOD:  想法 → [Analysis] → [PRD] → [Architecture] → [Stories] → [Implementation]
```

BMAD-METHOD 是**全周期**结构化框架——从产品构想到代码交付的完整流程。其核心优势在于显式上下文传递和角色专业化，但对中小型任务存在过重的问题。

### 设计方向：自适应分级规划

构建**自适应分级规划方法（Adaptive Tiered Planning）**：根据任务复杂度自动选择规划深度。

- Level 0: 即时执行（简单修改）
- Level 1: 快速规划（函数级任务）
- Level 2: 结构化规划（轻量 BMAD）
- Level 3: 全周期规划（完整 BMAD）
