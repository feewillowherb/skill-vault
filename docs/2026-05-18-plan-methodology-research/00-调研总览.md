# Cursor + OpenSpec + BMAD-METHOD 调研总览

## 概述

本次调研确立一套 **三工具分工、用户手工衔接** 的 epic 级开发方法论：

| 工具 | 角色 | 阶段 |
|------|------|------|
| **BMAD-METHOD** | Epic 规划、拆分、跨项目/前后端设计 | 规划与方案（止于 OpenSpec 可消费的 proposal） |
| **用户** | 将 BMAD 产出导入目标项目，启动各 OpenSpec change | 衔接层 |
| **OpenSpec** | 单 change 的 specs、design、**tasks**、实现与归档 | 执行与交付 |
| **Cursor** | 统一 IDE：承载 BMAD skills 与 OpenSpec `/opsx:*` 命令 | 全程 |

**调研日期**: 2026-05-18  
**调研来源**: `repos/bmad-method`、`repos/openspec`

## 核心原则

1. **用户自己衔接**：BMAD 不自动调用 OpenSpec；用户把 BMAD 拆出的每个 proposal（及关联 design）放入目标仓库后，再手动执行 OpenSpec 流程。
2. **任务清单归 OpenSpec**：BMAD **不得**产出 `tasks.md`、Story 任务列表、sprint 级实施清单；`tasks.md` 仅由 OpenSpec 在 propose/apply 链路中生成与维护。
3. **BMAD 专注「想清再做」**：PRD、架构、Epic 拆分、跨仓库/前后端概要设计、`project-context.md`；**跳过** BMAD Phase 4 Implementation。
4. **Cursor 双栈**：同一工作区安装 BMAD skills（`.agents/skills/`）与 OpenSpec（`openspec init` 生成的 skills/命令）。

## 工作流一览

```
Epic 需求
    │
    ▼
┌─────────────────────────────────────┐
│  Cursor + BMAD（Analysis → Solutioning）│
│  产出：PRD / 架构 / 多份 proposal 草稿   │
│        可选 design 概要、project-context │
│  禁止：tasks、Story 实施清单、sprint 驱动  │
└─────────────────────────────────────┘
    │
    ▼  【用户手工衔接】
    │  每个 proposal → 目标项目 openspec/changes/<id>/
    │  附上 BMAD design 作为 apply 参考
    ▼
┌─────────────────────────────────────┐
│  Cursor + OpenSpec（每个 change 独立）   │
│  /opsx:propose → specs → design → tasks │
│  /opsx:apply → /opsx:archive            │
└─────────────────────────────────────┘
```

## 快速开始

**在目标业务项目中（非本 vault 调研目录）：**

```bash
# 1. BMAD
npx bmad-method install --modules bmm --tools cursor

# 2. OpenSpec
npm install -g @fission-ai/openspec@latest
openspec init
```

在 Cursor 中：先用 `bmad-help` 完成 Epic 规划与拆分，再对每个子 proposal 使用 `/opsx:propose` 或基于 BMAD 草稿创建 change。
