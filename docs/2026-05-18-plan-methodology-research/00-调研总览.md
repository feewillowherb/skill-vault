# Plan 方法论调研总览

## 概述

本次调研围绕 **"AI 辅助开发中的 Plan-then-Execute 方法论"**，对 BMAD-METHOD 进行了深入分析，并确立了 BMAD-METHOD → Topic 文件夹 → OpenSpec 的标准工作流。

**调研日期**: 2026-05-18
**调研对象**: BMAD-METHOD v6
**调研来源**: BMAD-METHOD 源码 `repos/bmad-method`

## 工作流

```
用户需求 (epic 级)
      ↓
BMAD-METHOD 分析与规划
      ↓
生成制品:
  └── topic 文件夹/
      ├── proposal.md   ← OpenSpec /opsx:propose 输入
      └── design.md     ← OpenSpec /opsx:apply 参考（概要级别）
      ↓
导入 OpenSpec 执行 propose → apply 流程
```

### Topic 文件夹约定

- 文件夹名即为 topic 名称（如 `plan-methodology-research`）
- 每个文件夹包含 `proposal.md` 和 `design.md`
- `design.md` 保持概要级别，不需要非常细节
- 文件夹可直接导入 OpenSpec 启动工作流

## 核心发现

### BMAD-METHOD

| 维度 | 特征 |
|------|------|
| 定位 | 全生命周期 AI 敏捷开发框架 |
| 核心模式 | Analysis → Planning → Solutioning → Implementation 四阶段 |
| 人类控制 | 协作式（每个 Agent 引导用户思考） |
| 上下文管理 | 显式（文件化渐进传递） |
| 适用规模 | 想法级到企业级 |
| 制品管理 | 独立文档文件体系 |

### 工作流要点

- BMAD-METHOD 生成的 `proposal.md` 和 `design.md` 是 epic 级需求的标准制品
- Topic 文件夹是制品的存储单元，也是 OpenSpec 导入的单元
- OpenSpec 直接消费 topic 文件夹，无需额外的格式转换
