# Plan 方法论调研总览

## 调研概述

本次调研围绕 **"AI 辅助开发中的 Plan-then-Execute 方法论"** 这一主题，对 Cursor Plan Mode 和 BMAD-METHOD 两种主流方法论进行了全面的对比分析和研究。

**调研日期**: 2026-05-18
**调研对象**: Cursor Plan Mode、BMAD-METHOD v6
**调研来源**:
- BMAD-METHOD 源码: `repos/bmad-method`
- Cursor Plan Mode: 公开博客、社区讨论、官方文档

## 研究背景

AI 编程工具正在从"即时生成代码"的模式转向"先规划后执行"的结构化方法论。这一转变的核心动机是：

1. **降低返工成本**: 未规划直接编码导致大量架构返工
2. **提升代码质量**: 结构化规划产生更可维护的代码
3. **增强人类控制**: 人在回路中审批和修正计划
4. **上下文管理**: 分阶段传递上下文，避免 LLM 上下文窗口溢出

## 核心发现

### Cursor Plan Mode

| 维度 | 特征 |
|------|------|
| 定位 | IDE 内嵌的轻量级规划模式 |
| 核心模式 | Plan-then-Execute 二阶段 |
| 人类控制 | 审批式（Approve/Reject/Modify） |
| 上下文管理 | 隐式（由 IDE 管理） |
| 适用规模 | 函数级到模块级 |
| 制品管理 | Markdown 内嵌 |

### BMAD-METHOD

| 维度 | 特征 |
|------|------|
| 定位 | 全生命周期 AI 敏捷开发框架 |
| 核心模式 | Analysis → Planning → Solutioning → Implementation 四阶段 |
| 人类控制 | 协作式（每个 Agent 引导用户思考） |
| 上下文管理 | 显式（文件化渐进传递） |
| 适用规模 | 想法级到企业级 |
| 制品管理 | 独立文档文件体系 |

### 关键差异

```
Cursor Plan:  问题 → [Plan] → 审批 → [Execute]
BMAD-METHOD:  想法 → [Analysis] → [PRD] → [Architecture] → [Stories] → [Implementation]
```

Cursor Plan 是 **即时性** 的——在编码现场生成计划并执行；
BMAD-METHOD 是 **全周期** 的——从产品构想到代码交付的完整流程。
