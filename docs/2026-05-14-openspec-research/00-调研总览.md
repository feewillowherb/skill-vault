# Epic 需求 QA 分析功能调研总览

## 调研背景

本次调研旨在分析 GitHub 和 Skill 生态中是否存在用于分析 Epic 需求 QA（问答）的功能，重点关注需求落地过程中的需求管理、简易设计和提案草稿三个核心环节。

**调研时间**: 2026-05-14
**调研范围**: CodeRef Vault skill-vault 内已有内容
**调研重点**: Epic 需求分析、QA 问答功能、需求管理工具

## 调研发现

### 1. OpenSpec - 需求规范管理框架

**位置**: `repos/openspec/`
**类型**: 完整的需求管理和规范框架
**状态**: 活跃开发中

**核心功能**:
- 需求提案管理 (`/opsx:propose`)
- 需求探索分析 (`/opsx:explore`)
- 规范文档生成 (specs, design, tasks)
- 实现验证 (`/opsx:verify`)
- 变更归档管理 (`/opsx:archive`)

**支持的工作流程**:
1. 快速路径: `propose → apply → sync → archive`
2. 完整工作流: `new → continue → ff → apply → verify → archive`
3. 探索式: `explore → new → continue → ... → apply`

### 2. Impeccable - 前端设计计划文档结构

**位置**: `/repos/impeccable/`
**类型**: 前端 UI 设计 skill
**发现**: 包含结构化的计划文档模板

**计划文档结构** (`notes/plans/2026-04-28-001-feat-live-session-recovery-plan.md`):
- 问题框架 (Problem Frame)
- 需求追溯 (Requirements Trace)
- 范围边界 (Scope Boundaries)
- 上下文研究 (Context & Research)
- 关键技术决策 (Key Technical Decisions)
- 开放问题 (Open Questions)
- 输出结构 (Output Structure)
- 高层技术设计 (High-Level Technical Design)
- 实现单元 (Implementation Units)
- 系统级影响 (System-Wide Impact)
- 风险与依赖 (Risks & Dependencies)

### 3. 现有需求处理能力

**OpenSpec 的需求处理机制**:
- 结构化需求块解析 (`### Requirement:` 格式)
- 增量规范管理 (Delta Specs)
- 需求验证和实现一致性检查
- 多文件规范合并和冲突解决

**Impeccable 的计划管理**:
- 需求到实现的追溯链
- 技术决策记录
- 风险评估和缓解措施
- 实现单元分解

## 功能对比分析

| 功能维度 | OpenSpec | Impeccable | 缺失功能 |
|---------|----------|------------|---------|
| 需求提案 | ✅ 完整支持 | ⚠️ 间接支持 | - |
| 需求探索 | ✅ 专门的探索模式 | ❌ 无 | - |
| QA 问答 | ⚠️ 探索模式中有问答 | ❌ 无 | ❌ 专门的 QA 系统 |
| 简易设计 | ✅ design.md | ✅ 技术设计章节 | - |
| 提案草稿 | ✅ proposal.md | ✅ 概览章节 | - |
| 需求验证 | ✅ verify 命令 | ⚠️ 测试覆盖 | - |
| 文件分类 | ✅ 结构化目录 | ✅ 计划文档 | ❌ 统一标准 |

## 关键发现

### 现有优势
1. **OpenSpec 提供了完整的需求管理生命周期**
2. **Impeccable 展示了优秀的计划文档结构**
3. **两者都支持结构化的需求追溯**

### 功能空白
1. **缺少专门的 Epic 级别需求分析工具**
2. **没有专门的 QA 问答系统**
3. **缺少统一的需求分类和命名规范**
4. **需求到实现的自动追溯不够完善**

## 建议方向

基于调研结果，建议参考以下设计方向：

### 1. 文件分类规则
```
openspec/
├── epics/                    # Epic 级别需求
│   ├── EPIC-{id}-{name}/
│   │   ├── epic.md          # Epic 概览
│   │   ├── qa.md            # QA 问答记录
│   │   ├── requirements/    # 需求详情
│   │   └── design/          # 设计文档
├── changes/                  # 具体变更
└── specs/                    # 规范文档
```

### 2. 命名规范
- **Epic**: `EPIC-{YYYYMMDD}-{id}-{short-name}`
- **QA 文件**: `qa-{category}-{timestamp}.md`
- **需求文件**: `REQ-{id}-{description}.md`
- **设计文件**: `DES-{id}-{component}.md`

### 3. QA 系统设计要点
- 问题追踪和回答记录
- 需求澄清机制
- 决策历史追溯
- 利益相关者反馈集成
