# 文件分类和命名规范建议

## 规范设计原则

基于对 OpenSpec 和 Impeccable 的分析，制定以下文件分类和命名规范：

1. **一致性**: 统一的命名模式和目录结构
2. **可追溯性**: 从文件名就能理解内容关系
3. **可扩展性**: 支持不同规模的项目
4. **人机友好**: 既便于人理解，也便于机器解析

## 命名规范详解

### Epic 目录命名

#### 格式
```text
EPIC-{YYYYMMDD}-{id}-{short-name}
```

#### 组成部分
- **EPIC**: 固定前缀，大写
- **YYYYMMDD**: 创建日期，8位数字
- **id**: 序号，3位数字，从001开始
- **short-name**: 短名称，小写，连字符分隔

#### 示例
```
EPIC-20260514-001-user-auth          # 用户认证 Epic
EPIC-20260515-002-payment-integration # 支付集成 Epic
EPIC-20260516-003-dashboard-redesign  # 仪表板重新设计
```

#### 规则
1. **日期**: 使用 Epic 创建日期
2. **序号**: 项目内递增，不能重复
3. **短名称**: 
   - 只包含小写字母和连字符
   - 长度不超过 50 字符
   - 简洁描述 Epic 核心内容
   - 避免使用技术术语

### 需求文件命名

#### 格式
```text
REQ-{id}-{description}.md
```

#### 组成部分
- **REQ**: 固定前缀，大写
- **id**: 序号，3位数字，从001开始
- **description**: 需求描述，小写，连字符分隔
- **.md**: Markdown 扩展名

#### 示例
```
REQ-001-user-registration.md    # 用户注册需求
REQ-002-user-login.md           # 用户登录需求
REQ-003-password-reset.md       # 密码重置需求
REQ-004-session-management.md   # 会话管理需求
```

#### 规则
1. **序号**: Epic 内递增
2. **描述**:
   - 使用行为动词 + 名词
   - 小写字母，连字符分隔
   - 长度不超过 60 字符
   - 清晰描述需求内容

### 设计文件命名

#### 格式
```text
DES-{id}-{component}.{format}
```

#### 组成部分
- **DES**: 固定前缀，大写
- **id**: 序号，3位数字，从001开始
- **component**: 组件或模块名，小写，连字符分隔
- **.format**: 文件格式 (.md, .png, .svg 等)

#### 示例
```
DES-001-auth-ui.md              # 认证 UI 设计
DES-002-api-design.md           # API 设计
DES-003-security-design.md      # 安全设计
DES-004-database-schema.md     # 数据库设计
DES-005-component-structure.png # 组件结构图
```

#### 规则
1. **序号**: Epic 内递增
2. **组件名**:
   - 小写字母，连字符分隔
   - 描述设计的目标组件或方面
   - 长度不超过 60 字符

### 变更目录命名

#### 格式
```text
{verb}-{noun}
```

#### 组成部分
- **verb**: 动词，小写，描述操作类型
- **noun**: 名词，小写，描述变更对象
- 连字符分隔

#### 常用动词
```text
add:     添加新功能
fix:     修复问题
update:  更新现有功能
remove:  移除功能
refactor: 重构代码
improve: 改进性能或体验
optimize: 优化实现
```

#### 示例
```
add-login-form              # 添加登录表单
fix-auth-bug                # 修复认证 bug
update-user-profile         # 更新用户资料
remove-deprecated-api       # 移除废弃 API
refactor-auth-service       # 重构认证服务
improve-page-load           # 改进页面加载
optimize-query-performance  # 优化查询性能
```

#### 规则
1. **动词**: 使用上述动词列表之一
2. **名词**: 
   - 具体描述变更对象
   - 避免使用 "feature" 等通用词
   - 长度不超过 40 字符

### QA 记录文件命名

#### 格式
```text
qa.md (固定名称)
```

#### 说明
- 每个 Epic 目录下只有一个 `qa.md` 文件
- 包含该 Epic 的所有问答记录
- 内部使用标题分类组织

#### 内部组织结构
```markdown
# QA Record: {Epic Name}

## Open Questions
### Q001: {Question Title}
...

## Answered Questions
### Q002: {Previously answered question}
...

## Question Categories
### Functional
...
```

### 元数据文件命名

#### Epic 元数据
```text
metadata.yaml (固定名称)
```

#### 内容示例
```yaml
id: EPIC-20260514-001
name: user-authentication
status: active
priority: P0
created: 2026-05-14
updated: 2026-05-14
owner: product-team
stakeholders:
  - product-manager
  - tech-lead
  - ux-designer
related_epics: []
tags: [authentication, security, user-experience]
```

### 时间线文件命名

#### 格式
```text
timeline.md (固定名称)
```

#### 内容结构
```markdown
# Timeline: {Epic Name}

## Milestones
- **M1**: {里程碑描述} - {target_date}
- **M2**: {里程碑描述} - {target_date}

## Schedule
### Phase 1: {阶段名称}
- **Duration**: {开始日期} - {结束日期}
- **Deliverables**: 
  - {交付物 1}
  - {交付物 2}
```

## 版本控制建议

### Git 忽略规则
```text
# Epic 状态文件 (自动生成)
.epic-status.yaml

# Epic 临时文件
*.epic.tmp

# Epic 索引缓存
.epic-index.cache
```

### 分支策略
```text
# Epic 功能分支
epic/{epic-id}-{short-name}

# 示例
epic/EPIC-001-user-auth
epic/EPIC-002-payment-integration
```

## 兼容性考虑

### 向后兼容
1. **现有 OpenSpec 项目**: 可选择性启用 Epic 功能
2. **现有命令**: 保持所有现有命令不变
3. **现有目录结构**: 在现有结构基础上扩展

### 迁移策略
```bash
# 启用 Epic 功能
openspec config enable-epics

# 创建第一个 Epic
openspec epic new my-epic

# 将现有变更关联到 Epic
openspec epic link EPIC-001 add-login-form
```

## 最佳实践

### 文件组织
1. **一个 Epic 一个目录**: 保持 Epic 内容的独立性
2. **需求按功能分组**: 相关需求放在同一个 Epic 下
3. **设计与需求对应**: 每个设计文档明确关联需求

### 命名建议
1. **使用描述性名称**: 避免缩写和技术术语
2. **保持一致性**: 在项目中保持命名风格一致
3. **避免过长**: 文件名长度建议不超过 80 字符

### 文档维护
1. **定期更新**: 保持元数据和时间线的准确性
2. **版本控制**: 重要的决策和变更都要记录
3. **清理归档**: 定期归档完成的 Epic

## 错误示例

### ❌ 错误的 Epic 命名
```
EPIC-001                    # 缺少日期和描述
epic-20260514-user-auth     # 前缀应该大写
EPIC-20260514-1-user-auth   # ID 应该是3位数字
EPIC-20260514-001-UA        # 缩写不够描述性
```

### ❌ 错误的需求命名
```
requirement-001.md          # 应该使用 REQ 前缀
REQ-001.md                  # 缺少描述
REQ-authentication.md       # ID 缺失
REQ-001-very-long-user-registration-requirement-document.md # 名称过长
```

### ❌ 错误的变更命名
```
new-feature                 # 缺少具体描述
add-auth                   # 不够具体
fix-bug                    # 缺少 bug 描述
update                     # 缺少更新对象
```

## 工具支持

### 命令行工具
```bash
# 创建符合规范的 Epic
openspec epic new user-auth

# 验证文件命名
openspec validate names

# 重命名文件 (自动更新引用)
openspec rename REQ-001-old-name REQ-001-new-name

# 生成命名规范报告
openspec report naming-conventions
```
